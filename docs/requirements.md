# 📑 [기획 명세서] 여기저기 흩어진 "사고 싶은 것"들을 한 곳에 모아두는 상자 (WishBox)

## 1. 프로젝트 개요 (Overview)

- **프로젝트명**: 여기저기 흩어진 "사고 싶은 것"들을 한 곳에 모아두는 상자 (WishBox)
- **배경 및 문제 정의**:
    - 쇼핑몰뿐 아니라 여러 사이트에서 사고 싶은 게 자주 생기는 사용자가, 위시리스트가 여러 곳에 흩어져 있어 뭘 사려고 했는지 잊어버린다.
    - 여러 개 중 무엇을 먼저 살지 우선순위를 정하기 어렵다. 특히 "사야 하는 것"과 "그냥 사고 싶은 것"이 섞여 있어 단일 기준으로는 순위가 뒤엉킨다.
- **목표**: 사고 싶은 것들을 간단하게 기록할 수 있고, 필요도와 욕구를 함께 고려한 우선순위로 무엇을 먼저 사면 좋을지 사용자 입장에서 판단하기 쉽게 보여준다.

## 2. 핵심 기능 요구사항 (Requirements)

- **사용자 플로우**:
    - 메인 화면 ➔ 로컬 저장소에서 불러온 과거 항목 확인 ➔ 상품 추가 기록(모달 형식으로 입력) ➔ Refresh ➔ 갱신된 화면 확인
    - 메인 화면 ➔ 로컬 저장소에서 불러온 과거 항목 확인 ➔ 상품 삭제(되묻기 모달) ➔ Refresh ➔ 갱신된 화면 확인
- **로컬 저장소 연동**:
    - **항목 추가 시 데이터 적재**: 작성한 상품의 상세사항이 브라우저 로컬 DB(IndexedDB)에 저장되어야 하고, 삭제 시 상품 항목이 로컬 DB에서 사라져야 함. 로컬 DB가 유일한 데이터 소스이며, 별도의 서버 동기화는 없음.
    - **카운터 갱신**: 항목을 추가하거나 삭제할 때마다 화면의 상품 개수를 즉시 재계산해서 반영함 (네트워크 지연이 없으므로 실시간 구독 로직은 불필요).
- **데이터 보존 관련 주의사항**: 브라우저 캐시/사이트 데이터를 삭제하거나 시크릿(비공개) 모드로 접속하면 저장된 위시 항목이 모두 사라질 수 있음. 추후 클라우드 동기화가 필요해질 경우 Supabase 등으로 마이그레이션할 수 있도록 데이터 구조를 단순하게 유지함.
- **최초 접속 안내**: 홈 화면 최초 접속 시, 서비스 소개(핵심 기능 요약)와 "이 브라우저에만 저장된다"는 안내를 함께 담은 모달을 1회 노출함 (localStorage에 노출 여부 기록, 이후 재접속 시 노출하지 않음).
- **기본 카테고리 시딩**: 카테고리가 하나도 없는 최초 접속자에게는 기본 카테고리 3종("생필품", "의류", "취미")을 자동으로 생성해줌. 최초 1회만 시딩하며(localStorage 플래그로 관리), 사용자가 이후 전부 삭제하더라도 재생성되지 않음. 이름·색상 수정 및 삭제는 다른 카테고리와 동일하게 자유롭게 가능.

## 3. UI/UX 와이어프레임 가이드

### 3-1. 메인 화면 (Home)

**레이아웃 구조**

| 영역 | 구성 요소 | 세부 설명 |
|---|---|---|
| 헤더 | 타이틀 "WishBox" (좌측) + `[+ 새 항목]` 버튼 (우측) | 버튼은 스크롤 시에도 고정(sticky) |
| 카테고리 필터 바 | `[전체] [생필품] [의류] [취미] [+ 카테고리 관리]` 칩 UI | 가로 스크롤 가능, 다중 선택 가능. 기본 3종은 최초 접속 시 자동 생성됨 |
| 탭 & 정렬 | 좌측 `[살 것] [산 것]` 탭, 우측 `정렬 ▾` 드롭다운(펼침 화살표 아이콘 노출) | 정렬 옵션: 우선순위순 · 최근 추가순 · 가격 낮은순 · 가격 높은순 |
| 요약 배너 | "사고 싶은 것 총 N개 · 합계 금액" | "살 것" 탭에서 현재 선택된 카테고리 필터 기준으로 미구매 항목만 집계 (필터 없으면 전체 미구매 항목 기준), 가격 미입력 항목은 합계에서 제외하고 개수만 카운트 |
| 항목 카드 리스트 | 이미지 · 상품명 · 필요도/만족도 · 카테고리/가격 · 구매완료 체크박스 | 아래 카드 상세 참고 |

**항목 카드 상세**

- 좌측: 썸네일 이미지 (없으면 카테고리 색상 기반 기본 아이콘 노출)
- 중앙: 상품명(1줄 말줄임) / 카테고리 칩 1~2개 / 가격
- 우측: "필요"·"만족" 라벨과 함께 필요도·만족도를 각각 별도의 별점으로 표시(2×2 매트릭스를 하나의 조합 점수로 뭉개지 않고 두 축을 그대로 노출), "구매완료" 라벨이 붙은 체크박스
- 체크박스 선택 시: 별도의 삭제 연상 모션 없이 즉시 "산 것"으로 이동 (되돌리기 스낵바 3초 노출)
- 카드 클릭 시: 바로 수정 모달이 아니라 **상세 보기 모달**로 이동 (아래 3-2-1 참고)
- 롱프레스 또는 좌측 스와이프: 삭제 액션 노출

**상태별 화면**

- 로딩 중: 로컬 DB 조회는 즉시 완료되므로 별도 스켈레톤 없이 바로 리스트 렌더링 (초기 앱 실행 등으로 지연이 체감될 경우에만 짧게 스켈레톤 노출)
- 항목 0개(빈 상태): "아직 담아둔 게 없어요" + `[+ 새 항목]` 유도 버튼
- 카테고리 필터 결과 0개: "이 조건에 맞는 항목이 없어요" 안내와 필터 초기화 버튼
- 서비스 소개 및 데이터 소실 위험 안내: 홈 최초 접속 시, 서비스 소개(핵심 기능 3가지)와 "이 목록은 이 브라우저에만 저장돼요. 데이터를 지우면 사라질 수 있어요" 안내를 담은 모달 1회 노출

### 3-2. 항목 상세 보기 화면 (Modal)

- 등록된 항목을 카드에서 탭하면 뜨는 읽기 전용 모달
- 상품명, 이미지, 가격, 카테고리 칩, 필요도/만족도 별점, 우선순위 매트릭스 상 위치(예: "지금 사요"), 비고를 확인 가능
- 구매 링크가 있으면 "구매 링크 바로가기" 버튼으로 복붙 없이 새 탭에서 바로 이동 (없으면 "등록된 구매 링크가 없어요" 안내)
- 하단 좌측에 "삭제" 버튼(누르면 삭제 확인 다이얼로그로 연결), 우측에 `[닫기]` `[수정]` 버튼 — "수정"을 누르면 이 화면을 닫고 3-3 수정 모달로 전환

### 3-3. 항목 추가/수정 화면 (Modal)

**필드 순서 및 배치**

1. 상단: `새 위시 항목 추가` 타이틀 + 우측 닫기(X) 버튼
2. 상품명 입력 (`*` 필수 표시, 미입력 시 저장 버튼 비활성화 대신 저장 시도 시 인라인 에러 노출)
3. 선택 입력 그룹 (2열 배치로 "선택사항" 성격 구분)
   - 구매 링크 (URL 형식 검증)
   - 가격 (숫자만 입력, 통화 단위 자동 표시)
   - 이미지 (첨부 또는 링크 입력 중 선택, 미리보기와 첨부 버튼·링크 입력란의 세로 높이를 맞춰 비율 있게 배치)
   - 비고 (최대 200자, 글자 수 카운터 노출)
4. 카테고리 선택
   - "카테고리" 라벨 옆에 "(여러 개 선택 가능)" 안내 문구를 항상 노출해 다중 선택 가능함을 명시
   - 기존 카테고리 칩 노출 (다중 선택)
   - `+ 새 카테고리 만들기` 입력창이 칩 목록 하단에 상시 노출, 입력 후 Enter로 즉시 카테고리 생성 및 선택 (이미 있는 이름이면 새로 만들지 않고 기존 카테고리를 재사용)
5. **우선순위 선택 (필요도 × 욕구 2축)**
   - "필요도"와 "욕구/만족도" 두 항목을 각각 1~5점 버튼(전혀·조금·보통·꽤·매우)으로 선택
   - 두 값을 선택하면 화면에 미니 2x2 매트릭스 미리보기를 함께 노출해, 이 항목이 "지금 사요 / 꼭 필요해요 / 천천히 사도 돼요 / 다시 생각해봐요" 중 어디에 해당하는지 바로 확인 가능하게 함
   - 힌트 텍스트: 필요도는 "이게 없으면 지금 생활에 불편함이 있나요?", 욕구는 "이걸 가지면 얼마나 기쁠 것 같나요?"
   - 입력하다 만 내용은 저장하기 전이라도 로컬에 임시 저장되어, 실수로 모달을 닫아도 다음에 열면 복원됨 (저장 완료 시에만 임시 저장 데이터 삭제)
6. 하단 `[취소]` `[저장하기]` 버튼 — 로컬 저장은 즉시 처리되므로 별도 로딩 스피너 없이 클릭 즉시 모달이 닫히고 메인 화면 리스트가 갱신됨

### 3-4. 카테고리 관리 화면 (Modal)

- 등록된 카테고리를 리스트로 노출, 각 카테고리 옆에 `(N개 항목)` 연결 개수 표시
- 카테고리명 옆 색상 스와치 노출 (카테고리별 구분용, 칩 UI 색상과 연동)
- 카테고리별 `[수정] [삭제]` 버튼 배치
- 수정 클릭 시 카테고리명·색상을 인라인 편집 모드로 전환, 이미 존재하는 이름으로 바꾸려 하면 인라인 에러 노출
- 삭제 시 `이 카테고리가 붙은 N개 항목에서도 제거됩니다` 확인 문구 노출 + `[취소] [삭제]` 버튼
- 연결된 항목이 0개인 카테고리는 목록 하단에 별도로 묶어서 노출(정리 유도)
- 하단 `[+ 새 카테고리 추가]` 버튼 — 클릭 시 리스트 상단에 입력 행 추가, 이미 있는 이름이면 인라인 에러 노출

## 4. 로컬 상품 DB 필드 구조

**기술 스택**: 브라우저 IndexedDB 사용 (Dexie.js 래퍼 사용). localStorage는 카테고리 다대다 관계 같은 구조화된 다건 데이터 저장에 적합하지 않아 사용하지 않음 (단, 최초 안내 노출 여부·임시 저장 초안 등 단순 플래그/값 저장에는 localStorage를 사용). 서버가 없으므로 `id`는 클라이언트에서 `crypto.randomUUID()`로 생성하고, `created_at`/`updated_at`도 클라이언트 코드에서 직접 기록함.

### 4-1. `items` 테이블 (위시 항목)

| 필드명 | 타입 | 설명 | 제약조건 |
|---|---|---|---|
| `id` | UUID (text) | 항목 고유 식별자, `crypto.randomUUID()`로 생성 | PK |
| `title` | text | 상품명 | NOT NULL |
| `price` | integer | 가격(원 단위) | NULL 허용 |
| `purchase_link` | text | 구매 링크 URL | NULL 허용 |
| `image_url` | text | 썸네일 이미지 경로 또는 외부 URL | NULL 허용 |
| `memo` | text | 비고 (최대 200자) | NULL 허용 |
| `need_score` | integer | 필요도 (1~5) | NOT NULL, 기본값 3 |
| `want_score` | integer | 욕구/만족도 (1~5) | NOT NULL, 기본값 3 |
| `priority_score` | real | 정렬용 계산값, 예: `(need_score + want_score) / 2` | NOT NULL, 저장 시 자동 계산 |
| `is_purchased` | boolean | 구매 완료 여부 | NOT NULL, 기본값 false |
| `created_at` | timestamp | 생성 시각, 클라이언트에서 기록 | NOT NULL |
| `updated_at` | timestamp | 마지막 수정 시각, 클라이언트에서 기록 | NOT NULL |
| `purchased_at` | timestamp | 구매 완료 처리 시각 | NULL 허용 |

> `priority_score`는 정렬(우선순위순 정렬 옵션)에 사용하는 계산 필드로, 항목 저장/수정 시점에 `need_score`와 `want_score`로부터 다시 계산해 저장함. 홈 화면 카드/상세 모달에서는 이 값을 하나의 별점으로 뭉치지 않고, `need_score`·`want_score`를 각각 별도 별점으로 노출함.

### 4-2. `categories` 테이블 (카테고리, 구 `tags`)

| 필드명 | 타입 | 설명 | 제약조건 |
|---|---|---|---|
| `id` | UUID (text) | 카테고리 고유 식별자, `crypto.randomUUID()`로 생성 | PK |
| `name` | text | 카테고리명 | NOT NULL, UNIQUE |
| `color` | text | 카테고리 색상 코드(hex) | NOT NULL |
| `created_at` | timestamp | 생성 시각, 클라이언트에서 기록 | NOT NULL |

- 최초 접속자에게는 "생필품", "의류", "취미" 3종이 자동 생성됨 (2장 참고)

### 4-3. `item_categories` 테이블 (항목-카테고리 연결, 다대다, 구 `item_tags`)

| 필드명 | 타입 | 설명 | 제약조건 |
|---|---|---|---|
| `item_id` | UUID (text) | `items.id` 참조 | FK, NOT NULL |
| `category_id` | UUID (text) | `categories.id` 참조 | FK, NOT NULL |

- `item_id` + `category_id` 조합에 복합 UNIQUE 제약을 걸어 중복 연결 방지
- 카테고리 삭제 시 해당 카테고리의 `item_categories` 행을 함께 삭제(cascade)

> 이전 버전에서 사용하던 `tags` / `item_tags` 테이블은 앱 실행 시 Dexie 스키마 마이그레이션을 통해 `categories` / `item_categories`로 자동 이전됨.
